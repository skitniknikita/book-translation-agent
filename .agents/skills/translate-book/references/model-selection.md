# Model Selection for One Book

Before starting a new book, the lead obtains the current list of available models with `launch.py --catalog`. This sends a `model/list` request to the local Codex app-server: it does not perform inference and does not confirm that the account can complete a useful task. The catalog is collected page by page and saved in the selection itself, so resuming a book does not depend on a new model list.

The ordinary `launch.py --book <source>` runs one preparation session itself when no selection exists, validates the file, and only then starts the full cycle. There are no retries or fallback models in this transition. `--prepare` leaves the process at the selection stage. The preparation session sees the catalog and the official [App server: models](https://learn.chatgpt.com/docs/app-server#models) documentation, but does not translate the book or start workers. It writes `work/model-selection.json` in a separate output folder: by default, `<source without extension> — translation/`; use `--book-dir` for a different path. This is a considered decision, not automatic ranking by the model name, the `isDefault` flag, or any single catalog property.

The file contains `source.path`, `source.sha256`, and the duplicate `source_sha256`, `selected_at`, the complete `catalog` and `catalog_sha256`, and distinct `leader` and `worker`. Each role requires `model`, `reasoning_effort`, and `classification` with its exact role, rationale, and concrete evidence. `sources` retains the documentation link; `rationale` gives the allocation reason; and `account_access` always has the value `not_verified_by_catalog`.

The launcher checks that selected inference identifiers (`model`, or `id` in the old catalog) and reasoning levels are actually present in the saved catalog, all catalog pages were collected, the source hash matches, and role evidence is present. Each role needs a link to an official OpenAI model page: it records the basis, but does not automatically prove quality. For a new book, both selection and catalog must be no more than 14 days old; future dates are rejected. If the output folder already contains `work/state.json`, this is a resumption: selection is pinned and not automatically replaced, but its hashes and supported capabilities are still checked. `source.path` records provenance only, so moving the same book is permitted when its checksum matches. After the first useful inference, the lead records the model observed by the environment; that is the only practical confirmation of access when the environment reports it.

For offline verification and reproducible tests, pass `--catalog-file` with a normalized catalog, one `model/list` page, or a `pages` object.

The shared validation implementation ships inside the skill: `scripts/book_model_selection.py`; root-level `model_selection.py` is the launcher's import point. The book program validates the selection schema and hash again, so directly running the workflow does not bypass selection rules. The catalog is not evidence of quality or access: the actual run is recorded separately.
