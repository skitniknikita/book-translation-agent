# Агент перевода книг для Codex

ИИ исследует термины, переводит и редактирует. Программа готовит задания,
запоминает прогресс и собирает готовый текст в EPUB. Большая модель проверяет
смысл каждого блока; малые исполнители помогают с исследованием, черновиком
и русским языком. Конкретные модели выбираются перед новой книгой по доступному
каталогу и официальным данным, затем проверяются на фрагментах этой книги.

Агент отвечает на языке вашего обращения, если вы не попросили иначе. Язык
ответа не задаёт язык перевода книги: нынешний процесс по умолчанию переводит
на русский. Перевод на другие языки этим комплектом пока не проверен.

## Как пользоваться

1. Распакуйте всю папку, включая скрытые `.codex` и `.agents`.
2. Откройте её как проект Codex. Начните с доступной сильной модели. Astra/high
   в настройках — начальная модель подготовки, а не вечное требование к книге.
3. Создайте папку `books` внутри проекта. Добавьте туда книгу и, если есть, прежние
   глоссарии автора. Эта папка исключена из Git. Напишите:

> Используй $translate-book. Переведи книгу из books целиком на русский и собери EPUB.
> Все результаты сохрани внутри books, например в books/my-book-output.
> Перед началом проверь актуальные доступные модели: большая руководит и проверяет
> весь смысл, более экономные готовят черновики и редактируют русский.
> Сначала исследуй глоссарий по опубликованным переводам и надёжным источникам.
> Сохраняй прогресс программой из комплекта. Не меняй исходник.

Агент сам выполняет команды и проверки. Если скилл не обнаружен, попросите
прочитать `.agents/skills/translate-book/SKILL.md`. Уже открытый чат не меняет
модель от одной инструкции: если выбран другой руководитель, агент назовёт
его для выбора в интерфейсе. Автоматический переход между моделями до начала
основной сессии предусмотрен в запускателе CLI.

## Через запускатель

Нужны Python 3.11+ и актуальный Codex CLI с выполненным входом. Pandoc нужен для
EPUB. Комплект не устанавливает программы, не обновляет Codex, не читает ключи,
не подключает платный API и не меняет глобальные настройки.

```sh
python3 launch.py --check
python3 launch.py --book "books/Книга.epub" --dry-run
python3 launch.py --book "books/Книга.epub"
```

Обычный запуск без сохранённого выбора получает каталог моделей, запускает
одну подготовительную сессию, проверяет её решение и запускает основную сессию
выбранной большой моделью. Если подготовка не завершилась или решение не прошло
проверку, перевод не запускается. Выбор остаётся в папке книги; при продолжении
он не меняется из-за появления новинки. Прежде чем переводить большой объём,
агент проверяет реальный запуск исполнителя и качество двух пробных фрагментов.

Результат по умолчанию — отдельная папка `Книга — перевод` рядом с исходником.
Можно указать `--book-dir "Автор — Название"`. Путь к исходнику и папке результата
разрешается относительно папки комплекта. Для ручной проверки доступны:

```sh
python3 launch.py --catalog
python3 launch.py --book "books/Книга.epub" --prepare
python3 launch.py --book "books/Книга.epub" --selection "books/Книга — перевод/work/model-selection.json" --check
```

`--check` и `--dry-run` не запускают модели. `--catalog` получает каталог без
генерации текста, но может обращаться к службе Codex; каталог может быть
кешированным и не доказывает доступ к модели. Подготовка выбора и сам перевод
используют подписку. API-цены не равны расходу лимитов подписки.

В Windows команда может называться `py -3`; для запускателя нужен нативный
`codex.exe`, а не `.cmd/.bat`. Реальный запуск на Windows/Linux не проверен.

## Что изменилось

- Программа сохраняет оригинал, полный список блоков, задания и версии. После
  остановки показывает, с какого этапа продолжить. Готовые части не нужно
  переводить повторно ради нового чата.
- Исполнители получают свою часть текста, нужные термины и проверенный контекст.
  Полная история и большой реестр источников не пересылаются каждому.
- Проверки привязаны к конкретной версии. Правка текста, термина, общего правила,
  модели или зависимого конспекта делает соответствующую приёмку неактуальной.
- База терминов автора сохраняет источники и разные контекстные решения.
  Обязательное интернет-исследование новой книги остаётся.
- Простые части можно укрупнять после калибровки; плотная философия остаётся
  небольшими заданиями. Блоки и аргументы не обрезаются под лимит слов.
- Порядок «сначала русский, потом смысл» поддержан как проверяемый вариант.
  По умолчанию сохраняется прежний порядок. Новый включается только после
  сравнения на первой главе с отдельными результатами и оценкой руководителя.
- Pandoc собирает EPUB из принятого текста. Неудачная сборка сохраняет предыдущий
  EPUB. Ручные правки итогового Markdown не затираются молча.
- Иллюстрации сохраняются, подписи переводятся. Надписи внутри схем агент
  распознаёт, сверяет и переводит рядом с оригиналом; автоматическая перерисовка
  не входит в комплект.

## Результат и продолжение

В папке книги: `00_Глоссарий.md`, `01_Перевод.md`, при необходимости примечания,
метаданные, EPUB, `03_Проверки.md` и рабочая папка `work`.

Для продолжения: «Продолжи эту книгу по сохранённому состоянию. Сначала проверь
актуальность файлов и моделей». Это продолжение по файлам, а не фоновая работа:
сам по расписанию комплект не запускается.

Прежние книги с ручным журналом schema 1 автоматически не мигрируются. Агент
продолжает их по прежнему протоколу. Новая программа использует schema 2.

## Проверка и устройство

```sh
python3 -m unittest discover -s tests -v
```

Тесты проверяют полноту, продолжение, устаревание проверок, выбор моделей,
безопасное применение правок и реальную сборку/обратное чтение EPUB через Pandoc.
Синтетические тестовые записи ревью не являются доказательством качества
перевода. Сравнение моделей и порядка редактуры проводится на материале книги.

- `.agents/skills/translate-book/SKILL.md` — инструкция агента.
- `references/translation-protocol.md` внутри скилла — переводческие требования.
- `references/automation.md` — команды, форматы заданий и подтверждений.
- `references/model-selection.md` — выбор и закрепление моделей.
- `scripts/book_workflow.py` — задания, прогресс, версии и сборка.
- `scripts/epub_builder.py` — упаковка и структурная проверка EPUB.
- `launch.py`, `model_selection.py` — подготовка выбора и запуск Codex.

## Ограничения

Скрипты не доказывают смысловую точность и достоверность источников; это работа
моделей и редактора. Извлечение PDF/OCR проверяется отдельно. Полноценный EPUBCheck
не подменяется проверками ZIP/XML/ссылок, его отсутствие отмечается в отчёте.
Фактическая экономия на целой книге пока не измерена.

Для запуска нужен клиент с поддержкой выбранных моделей. Комплект не обходит
ограничения подписки. Если начальная модель из `.codex/config.toml` недоступна,
выберите доступную сильную модель подготовки; сами модели для книги затем
подбираются по текущим данным. Не используйте малую модель в роли руководителя.

Основа — собственный переводческий протокол; код и тексты книг BookTrans сюда
не скопированы. При разборе [BookTrans](https://github.com/sukamenev/booktrans)
обсуждались сохранение состояния и компактный контекст. Выбор моделей опирается
на [официальный каталог Codex](https://learn.chatgpt.com/docs/app-server#models)
и [документацию субагентов](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## Проект на GitHub

Основная документация и инструкции агента теперь на английском. Русский остаётся
языком перевода по умолчанию. Есть [учебный пример](examples/README.md),
[правила участия](CONTRIBUTING.md) и [простая инструкция по публикации](docs/PUBLISHING.ru.md).
Книги и результаты храните в `books/` или вне репозитория.

Перед публикацией выполняются тесты и проверка состава архива:

```sh
python3 -m unittest discover -s tests -v
python3 tools/release.py --check
```

Проверки GitHub Actions подготовлены; успешный запуск на GitHub можно подтвердить
только после публикации. Работа моделей использует сервис Codex — это не полностью
автономный перевод на компьютере без отправки текста.
